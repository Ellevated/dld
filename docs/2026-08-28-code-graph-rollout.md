**Дата:** 2026-08-28 · **Ветка:** develop · **Коммиты:** `5bbace6`, `1e05697`, `1583b53` (+ по одному в семи репо)

Отправная точка — вопрос «посмотри репо Graphify, может пригодиться». Инструмент не взяли; вместо
этого выяснилось, что уже стоящий у нас граф кода никем не использовался, а после настройки он

## 1. Что было

## 2. Три ошибки, которые пришлось признать по дороге

| Утверждение | Чем оказалось |
|---|---|
| «Сверяй `head_sha` с `git rev-parse HEAD`, чтобы понять, свежий ли граф» | `head_sha` читается из git **на лету** и всегда равен HEAD. Проверка была мёртвой с момента написания |
| «Тогда сверяй `detect_changes`» | Это git-diff против base_branch (812 файлов на develop), а не дрейф индекса |
| «Граф не покрывает промпт-дерево, и это непреодолимо» | Верно лишь для конфигурации по умолчанию. `.cbmignore` с `!.claude/` снимает ограничение |

Надёжного индикатора свежести у инструмента нет. Промпты теперь говорят **«пересобери»**, а не
«проверь»: пересборка и есть проверка.

## 5. Детектор рассинхрона деревьев

`scripts/check-tree-sync.py` — сравнивает **тела функций**, а не файлы.

`diff -r` здесь бесполезен: `.claude/` и `template/.claude/` **обязаны** отличаться прозой —
спек-id вырезаны, шапки переписаны, формулировки смягчены. Скрипт берёт из графа границы функций
и сравнивает тела по этим границам: переписанный комментарий над кодом молчит, изменённый regex
виден сразу.

Два очевидных подхода проверены и отброшены — **оба врут**:

- **рёбра `SIMILAR_TO`**: 33 «находки», из них 30 — файлы с нулевым diff (порог ~0.95, у многих
  идентичных пар ребра просто нет)
- **метрики** `lines`/`complexity`/`cognitive`: совпали на реальной односторонней правке, потому
  что она не изменила число строк

Граф используется там, где он точен — структура, — и ни для чего более размытого.

### Проверка с двух сторон

**Со стороны фактов:** все 4 находки подтверждены реальным `diff` (17/12/11/5 строк расхождения);
четыре контрольных файла с нулевым diff детектор не тронул.

**Со стороны эксперимента:** правка **одной строки** в template (`some` → `every`, число строк не
изменилось — ровно тот случай, где метрики слепы) поймана как пятая находка; откат вернул счёт к
четырём.

### Что нашлось в DLD прямо сейчас

| Функция | Расхождение |
|---|---|
| `hooks/post-edit.mjs::main` | 15 строк |
| `hooks/prompt-guard.mjs::main` | 10 строк |
| `hooks/session-end.mjs::main` | 9 строк |
| `hooks/utils.mjs::extractAllowedFiles` | 5 строк |

Первые три — одно и то же: в `template/` есть отладочное инструментирование хуков
(`debugLog`/`debugTiming`), которого root не получил. Четвёртое — обратное: в root есть фикс
(снятие маркера списка перед матчем пути), которого нет в template; без него allowlist-парсер
захватывает голый `-` как путь.

**Ни одно из четырёх не описано в `template-sync.md` как намеренное.**

## 6. Расхождения закрыты (в тот же день)

**Кто отстал:** коммит `426e9e4` (BUG-099, debug observability) затронул **только template** —
девять файлов, root не получил ничего. При этом `debugLog`/`debugTiming` лежат в обоих
`utils.mjs`; в root они просто нигде не подключены. Отстал root.

- три хука (`post-edit`, `prompt-guard`, `session-end`) перенесены из template в root —
  расхождение было на 100% debug-слоем, вне него оставались только строки импорта;
- фикс `extractAllowedFiles` перенесён обратно, root → template. Девять тестов
  `extractAllowedFiles` зелёные. Одно падение в сьюте (`getProjectDir` ждёт `/tmp`-путь на
  Windows) проверено через `git stash` — оно предшествует правке.

Детектор после правок: **`clean`, exit 0**.

**Побочная находка, записанная в `template-sync.md`:** в root нет `.claude/hooks/__tests__/`
вообще — десять тестовых файлов существуют только в template, root гоняет те же хуки без
единого теста. Детектор такие дыры не ловит по устройству: он сравнивает функции в файлах,
которые есть в **обоих** деревьях. Портировать сьюту вслепую нельзя — она падает на Windows.

## 7. CI — и почему он был красным четверо суток

Детектор повешен в job `prompt-integrity`. На runner'е бинаря нет, поэтому без дополнительной
меры шаг был бы вечнозелёным — та самая поломка, ради которой всё затевалось. Меры две:

1. **`--require-graph`** — превращает любой путь «недоступно» в exit 2. Локально отсутствие
   инструмента не должно ронять чужой коммит; в CI оно означает, что проверка ничего не
   измерила, и это провал. Проверено: без флага exit 0, с флагом exit 2.
2. **Бинарь закреплён версией и sha256** (`v0.10.8`, `e5cba4c…`, сверен вручную). Это
   сторонний код, исполняемый в CI; `latest` позволил бы апстриму менять то, что здесь
   выполняется.

**Попутно вскрылось важнее самого шага:** `python-lint` падал с 24 августа — двенадцать
прогонов подряд. Коммит `141bf10` добавил код, не прогнав `ruff format`; локально это не
ловилось, потому что проверялся `ruff check`, а падал `ruff format --check`. Форматирование
сделано ruff **0.16.1** — той версией, что закреплена в CI: разные версии форматируют
по-разному, и починка локальной 0.14.6 оставила бы CI красным.

Детектор на CI, который никто не смотрит четвёртые сутки, — тот же инструмент-без-сигнала,
ради которого всё затевалось.

### Четыре прогона до зелёного

Шаг не заработал с первого раза, и каждая причина была отдельной:

| Прогон | Падение | Настоящая причина |
|---|---|---|
| 1 | `query_graph returned no JSON` | CLI 0.10.8 печатает человекочитаемую таблицу, `--json` не передавался |
| 2 | то же | диагностика печатала только stderr, где лежат строки логгера — stdout не показывался |
| 3 | `the graph holds no functions` | `--json` оборачивает конверт, но **не** полезную нагрузку |
| 4 | то же | у `query_graph` нет `structuredContent` вовсе; `content[0].text` — та же таблица |

Первые три раза причина устанавливалась догадкой. Четвёртый — диагностическим прогоном,
печатавшим сырой конверт; он и дал факт:

```json
{"content":[{"type":"text","text":"rows: 2  (cols: f)
  template/...
total: 2
"}],
 "isError":false}
```

Отсюда парсер таблицы (`rows: N (cols: …)`, строки с отступом, значения через `shlex` — они
shell-quoted). Проверен на дословном выводе из лога, а не на придуманном образце.

Попутно закрыт отдельный класс молчания: неудачный вызов тула возвращает exit 0 и корректный
конверт, а единственный признак — поле `isError`, которое не проверялось. Развёрнутый без
проверки конверт давал пустой результат, неотличимый от «ничего не нашлось».

### Проверка самого CI-шага — тоже с двух сторон

- **на чистом дереве:** `113 root symbols, 135 template symbols, 113 twins compared, clean` —
  цифры совпали с локальными, то есть на runner'е выполняется ровно та же работа;
- **на внесённом рассинхроне:** отдельная ветка с правкой одной строки в template →
  `DIVERGED — hooks/pre-edit.mjs::isTestFile`, job красный. PR закрыт, ветка удалена.

Зелёный шаг, который не умеет краснеть, доказательством не является.
