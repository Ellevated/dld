## F1: "impl-merged-on-develop" guard logic is duplicated + chronically fragile (SSOT gap)

**Frequency:** 3+ (cross-session + incident history).
**Evidence:**
- SIGNAL-2026-06-06-0001 — two independent guards check the same fact:
  `callback._is_done_on_develop` (origin/develop → bool) and
  `gate_logic.find_implementation_commit` (shadow gate-daemon → SHA). Both
  duplicate subject-match + Allowed-Files-path logic. FF-09 deliberately kept
  them separate (gate_logic must not import callback), so the duplication is
  structural, not accidental.
- SIGNAL-2026-05-23-2300 (prior session F3) — same subject-match logic is the
  exact surface that re-introduces TECH-177 if anyone reverts to bare `--grep`
  (body/trailer false-match). Migration docs already mischaracterize it.
- Incident history concentrated here: TECH-176 (auto-close), TECH-177 (subject vs
  body), TECH-197 / BUG-1117 (timeout-interrupted push), `cefaa55` rename
  `_spec_has_merged_implementation` → `_is_done_on_develop`.

**Type:** design_decision / failure_pattern (duplicated business rule, no single owner).

**External validation (Exa):**
- thehardparts.dev "Business logic leaks across layers": the smell is "same rule
  partially duplicated across layers; need a *rule ownership map* + decide which
  layer is canonical." Explicit warning: **AI continues the nearest local pattern,
  spreading copied business rules faster** — and "generated syntactic consistency
  hides inconsistency in actual source of truth." Anti-fix to avoid: "fixing the
  visible instance without tracing all copies."
- SE.SE / Leandro Luque: same-language modules should share one validation
  library/function so the rule changes in exactly one place.

**Proposed action (matches SIGNAL-2026-06-06 suggested action):**
- After TECH-197 stabilizes, extract a single pure function
  `is_implementation_on_develop(repo, spec_id, allowed) -> SHA | None` — the SSOT
  for subject + path matching — imported by **both** callback and gate-daemon.
  Resolves the FF-09 "no callback import" constraint by giving both a third,
  dependency-free module (pattern: shared library, not a runtime service).
- Add a one-line "rule ownership" pointer in `dependencies.md`: this matching
  rule lives in ONE place; never re-implement inline.

**Risk if ignored:** the two copies drift; a fix lands in one guard but not the
other; or a future agent "continues the nearest pattern" and reverts to bare
`--grep` → TECH-177 false-done class re-emerges. This is the single most-patched
fragility surface in the orchestrator.
