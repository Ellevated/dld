### F2: Callback продолжает циклически закрывать спек (новое свидетельство)

**Severity:** Critical
**Reproducibility:** Постоянно повторяется каждый раз когда founder ручкой откатывает Status в queued.

`callback_decisions` для ARCH-186 (последние 24h):

```
780  08:42:58Z  sync    fixed                      demoted=0   ← false-positive auto-close
781  08:48:55Z  demote  no_implementation_commits  demoted=1
782  08:48:55Z  sync    spec_already_done          demoted=0   ← в той же транзакции снова done
995  10:23:15Z  sync    spec_already_done          demoted=0
996  10:26:26Z  demote  no_implementation_commits  demoted=1
997  10:26:26Z  sync    spec_already_done          demoted=0   ← снова в той же транзакции
998  10:32:41Z  demote  no_implementation_commits  demoted=1
999  10:32:41Z  sync    spec_already_done          demoted=0   ← снова
```

**Новый симптом:** В одном вызове callback'а сначала срабатывает «нет implementation commits, демоутим» (verdict=demote, demoted=1), но **сразу же** во второй проверке guard видит spec.md уже с `Status: done` (от предыдущего цикла) и пишет sync с verdict `spec_already_done`. То есть demote_in_transaction отменяется тем же запуском.

**Hypothesis:** в `verify_status_sync` сначала вызывается activity-check, потом existence-check; activity-check решает демоутить, existence-check видит «done в spec.md» и трактует как «уже сделано — не трогаем». Это double-check race в одном процессе.

**User impact:** Любой ручной revert founder'а откатывается следующим cycle'ом callback'а. Спек физически нельзя удержать в `queued` без хотфикса самого callback'а.

### F3: ACTION REQUIRED игнорируется guard'ом

**Severity:** Major
**Reproducibility:** Always

Спек содержит явный блок:

```
## ⚠️ ACTION REQUIRED: HUMAN REVIEW BEFORE AUTOPILOT

Это R1 P0 — state machine migration. Founder должен прочитать spec
и явно отпустить в autopilot перед запуском. Не auto-handoff.
Никаких exceptions.
```

Несмотря на это, callback всё равно меняет Status (как demote, так и sync→done) без human-in-the-loop. Это нарушает контракт спека.

**User impact:** Высокорисковые спеки не защищены от автоматических state-flips guard'а.
