## Failures

### F1: Digest header always says "(last 24h)" regardless of --since-hours

**Severity:** Minor
**Reproducibility:** Always
**Expected:** When user passes `--since-hours 720`, output header should say "(last 720h)" or similar.
**Actual:** Header is hardcoded to "(last 24h)".

**Steps to reproduce:**
```
python3 scripts/vps/audit_digest.py --dry-run --since-hours 720
```
Output:
```
Callback digest 02.05 (last 24h)        ← still "24h"!
  dld: 1 done, 0 demote
```

**Evidence:** `audit_digest.py:104` and `:124` — string literal `"last 24h"`.
**User impact:** Operator running ad-hoc digest with custom window gets confusing/incorrect summary text — easy to misread "last 24h" while looking at week-long data.
**Hint:** `f"Callback digest {date_label} (last {hours}h)"` — pass `hours` into `render()`.

---

### F2: CLI flag names diverge from spec

**Severity:** Minor
**Reproducibility:** Always
**Expected:** Spec Task 4 documents `--log` and `--hours`. Tests in `tests/integration/test_audit_digest.py` (per spec) referenced `--log`/`--hours`.
**Actual:** Implementation uses `--audit-log` and `--since-hours`.

**Steps to reproduce:**
```
python3 scripts/vps/audit_digest.py --hours 24
# error: unrecognized arguments: --hours 24
```

**User impact:** Spec readers and external scripts following the spec will fail with `error: unrecognized arguments`. Internal tests were rewritten to match implementation, so test suite passes — but spec is now stale documentation.
**Hint:** Either add `--log`/`--hours` as aliases, or update spec to reflect actual flag names.

---

### F3: Cron entry not installed on current host

**Severity:** Major
**Reproducibility:** Always (on this host)
**Expected:** Spec Task 5 — running `setup-vps.sh --phase3` adds idempotent `0 9 * * *` cron entry.
**Actual:**
```
crontab -l | grep audit_digest
(empty)
```

**Steps to reproduce:** `crontab -l 2>/dev/null | grep audit_digest` returns nothing.
**User impact:** Daily digest will not fire automatically. Whoever deployed TECH-171 must rerun `setup-vps.sh --phase3` (or install the cron line manually) — otherwise the whole "daily summary" feature is dormant. This is the headline goal of the spec.
**Hint:** Run `bash scripts/vps/setup-vps.sh --phase3` on the VPS host. Or this dev box may simply not be where the cron should live (orchestrator host vs dev clone) — verify on the orchestrator host.

---

### F4: Logrotate config not installed on current host

**Severity:** Major
**Reproducibility:** Always (on this host)
**Expected:** Spec Task 6 — `/etc/logrotate.d/dld-callback-audit` installed by `--phase3`.
**Actual:** File does not exist.

**Steps to reproduce:** `ls /etc/logrotate.d/dld-callback-audit` → "No such file or directory".
**User impact:** `callback-audit.jsonl` will grow unbounded with no 30-day retention. Disk pressure long-term, and the spec's stated retention policy is not enforced.
**Hint:** Same as F3 — run `--phase3` on the deploy host (it requires sudo for `/etc/logrotate.d`).

---

### F5: Digest output missing 📊 emoji from spec mockup

**Severity:** Cosmetic
**Reproducibility:** Always
**Expected (spec):** `📊 Callback digest 02.05 (last 24h)`
**Actual:** `Callback digest 02.05 (last 24h)` (no emoji)

**User impact:** Telegram message looks plainer than designed; harder to spot in a busy chat. Trivial.
**Hint:** Prepend `"📊 "` in `render()`.
