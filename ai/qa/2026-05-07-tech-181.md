## Failures

### F1: Running orchestrator daemon still uses pre-TECH-181 code (deploy lag)

**Severity:** Major
**Reproducibility:** Always (until service is restarted)
**Expected:** After commit 7a2e699 lands on `develop`, orchestrator picks up `Status: queued` items and ignores legacy `Status: new`.
**Actual:** Daemon PID 3760568 started 2026-05-07 16:32:38 — six hours before the commit was created (22:48:45). Process still holds the previous module in memory; on disk the file is updated but `scan_inbox()` in the running process still matches `**Status:** new`.

**Steps to reproduce:**
1. `systemctl --user show dld-orchestrator -p ActiveEnterTimestamp` → 16:32:38
2. `git log -1 --format=%ai scripts/vps/orchestrator.py` → 22:48:45
3. `journalctl --user -u dld-orchestrator --since today | grep "processing inbox"` → empty for project `dld`, even though `ai/inbox/20260507-hermes-intake-bridge-status-gate.md` has `**Status:** queued` since 22:21:37 and has been sitting through 5+ scan cycles.

**Evidence:**
- File mtime: `2026-05-07 22:21:37` for `ai/inbox/20260507-hermes-intake-bridge-status-gate.md`
- No `processing inbox: dld/...` log line in 6h of cycles
- Regex against the file from a fresh interpreter (`python3 -c "import re; ..."`) returns match=True at pos 102 — proves new code would dispatch it.

**User impact:** Hermes-promoted items appear stuck in the inbox until an operator restarts the service. The clean-break contract is unenforceable while daemon holds stale code.

**Hint for developers:** Add `systemctl --user restart dld-orchestrator` to the rollout checklist for TECH-181, or wire ADR-021 rollout into the spec's acceptance section. Long-term: signal-reload on file change, or a watchdog that restarts when `scripts/vps/orchestrator.py` mtime > daemon start time.

### F2: `ai/inbox/README.md` will be dispatched as an inbox item after restart (false positive)

**Severity:** Critical
**Reproducibility:** Always (after F1 is fixed and daemon restarts)
**Expected:** Documentation files in `ai/inbox/` are not treated as actionable inbox items.
**Actual:** New `scan_inbox()` regex `\*\*Status:\*\*\s*queued` matches **any** occurrence in the file. `ai/inbox/README.md` (created by autopilot at 22:48:58 as part of TECH-181 acceptance) contains the literal token `**Status:** queued` inside the documentation table at lines 9 and 22. When the daemon restarts and runs the new code, it will:

1. Read README.md
2. Match the regex on line 9 / 22
3. Rewrite first match to `**Status:** processing`, mangling the contract docs
4. Move `README.md` → `ai/inbox/done/README.md`
5. Submit a Spark task with the README contents as the prompt

**Steps to reproduce:**
```bash
python3 -c "
import re, pathlib
rx = re.compile(r'\*\*Status:\*\*\s*queued', re.IGNORECASE)
text = pathlib.Path('ai/inbox/README.md').read_text()
print('match:', bool(rx.search(text)))   # → True
"
# grep verification
grep -nE '\*\*Status:\*\*' ai/inbox/README.md
# → 9: ...field `**Status:** <state>`
# → 22: ...файлы с `**Status:** queued`. Любой другой статус игнорируется и
# → 52: **Status:** draft
```

**Evidence:** README has its own `**Status:** draft` declaration at line 52 (the *intended* status field), but the regex picks up the earlier illustrative mention of `queued` first.

**User impact:** First post-restart cycle for project `dld` will: corrupt README, file a phantom Spark spec, burn a compute slot, and remove the new contract docs from the place where Hermes/operator look for them. Cleanup requires manual `git restore` + pueue task kill.

**Hint for developers:** Two cheap fixes; pick one:
1. Skip files named `README.md` / `README.*` explicitly in `scan_inbox()`.
2. Anchor the regex to a top-of-file YAML/header position (e.g. only the first 20 lines, or require it be the only `**Status:**` declaration). The existing `_parse_inbox_file()` helper likely already parses the header — reuse it instead of two separate regex passes.

Also: in `ai/inbox/README.md` itself, escape the example so the regex can't match — e.g. `` `**Status:**` `` `queued` (split across backticks), or wrap examples in a fenced code block and exclude code blocks from the scan.
