## Failures

### F1: pre-commit hook ложно ругается на правки ВНЕ marker-блока

**Severity:** Major
**Reproducibility:** Always
**Expected:** По спеке (Task 4 Acceptance): «Touching prose outside markers → silent». Хук должен молчать, если diff не задевает блок.
**Actual:** Хук печатает warning при любой правке `ai/features/*.md`, в которой файл содержит marker-блок — даже если изменения добавлены ПОСЛЕ закрывающего `<!-- DLD-CALLBACK-MARKER-END -->`.

**Steps to reproduce:**
```bash
cd /tmp && rm -rf qa && mkdir qa && cd qa && git init -q
git config user.email t@t && git config user.name t
git config core.hooksPath /home/dld/projects/dld/.git-hooks
mkdir -p ai/features scripts/vps
cp /home/dld/projects/dld/scripts/vps/spec_lint.py scripts/vps/
cat > ai/features/TECH-999.md <<'EOF'
<!-- DLD-CALLBACK-MARKER-START v1 -->
## Allowed Files

<!-- callback-allowlist v1 -->

- `a.py`

<!-- DLD-CALLBACK-MARKER-END -->
EOF
git add -A && git commit -q -m init
printf '\n\nextra prose only\n' >> ai/features/TECH-999.md
git add -A && git commit -m "outside markers"
```

Видим warning, хотя дифф `@@ -10,0 +11,3 @@` лежит ПОСЛЕ END (строка 9).

**Evidence:** `python3 scripts/vps/spec_lint.py --diff-warn ai/features/TECH-999.md` → `exit=2` для outside-markers diff.

**User impact:** Hook будет шуметь на каждом легитимном редактировании спек (добавление текста в `## Drift Log`, `## Autopilot Log`, любые секции вне Allowed Files). Alarm fatigue: операторы привыкнут игнорировать предупреждение, и реальная правка allowlist пройдёт незамеченной — это убивает весь смысл TECH-175 Task 4.

**Hint for developers:** В `scripts/vps/spec_lint.py::_diff_intersects_marker_block` цикл по строкам diff не пропускает заголовки `---a/...` и `+++b/...`. Строка `---a/file.md` начинается с `-`, и при `new_line=0` (до первого `@@`) попадает в `_is_inside_any_block(0, ...)` — а индекс 0 это START первого блока, значит «внутри». Фикс в 1–2 строки: пропускать строки, начинающиеся с `---`/`+++`/`diff `/`index `, до первого hunk header.

### F2: Spec TECH-175 сам не проходит свой же линтер

**Severity:** Minor
**Reproducibility:** Always
**Expected:** Спека про hardening маркеров должна сама использовать markers (dogfooding). По EC-6 / Task 3 Acceptance — все callback-owned секции обёрнуты.
**Actual:**
```
$ python3 scripts/vps/spec_lint.py ai/features/TECH-175-2026-05-02-spark-spec-template-hardening.md
LINT_E005_UNKNOWN_VERSION ai/features/TECH-175-...:530 v9
LINT_E006_ALLOWED_FILES_OUTSIDE_BLOCK ai/features/TECH-175-...:59
exit=1
```

`## Allowed Files` в самой TECH-175 НЕ обёрнута маркером, плюс пример `v9` внутри тестовой выкладки (строка 530) парсится линтером как настоящий неподдерживаемый блок.

**User impact:** Если/когда CI начнёт прогонять `spec_lint.py` на всех `ai/features/*.md`, TECH-175 будет ронять CI. Также подрывает доверие — «инструмент, который не валидирует свою же спеку».

**Hint for developers:**
1. Обернуть `## Allowed Files` в TECH-175 в `<!-- DLD-CALLBACK-MARKER-START v1 -->...END -->`.
2. Примеры регэксов и кода в спеке поместить в fenced code block — линтер должен игнорировать строки внутри ` ```...``` ` (сейчас не игнорирует — это потенциальный отдельный баг, общий для любого spec'а с примерами).

## Observations (не баги, но к сведению)

- **EC-2 + `--legacy-ok` неполный:** spec_lint с `--legacy-ok` всё равно exit=1 на legacy-спеке без markers, потому что параллельно возникает `LINT_E006_ALLOWED_FILES_OUTSIDE_BLOCK`, который не понижается флагом. Получается, ни одна legacy-спека не пройдёт линтер даже в legacy-режиме. Это противоречит формулировке EC-2 («fallback на TECH-167 logic») если предполагается, что legacy-режим должен возвращать exit 0 для валидных legacy-спек. Стоит уточнить семантику или расширить `--legacy-ok` на E006.
- **Pre-commit hook печатает warning дважды** в одном коммите при правке внутри блока — мелкий шум, отдельно от F1.
