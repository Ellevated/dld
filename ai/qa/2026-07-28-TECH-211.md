## Failures

### F1: Reaper не запускается в проде вообще

**Severity:** Critical
**Reproducibility:** Always
**Expected:** `heartbeat_reaper.py` крутится каждые 5 минут (так его ставит `setup-vps.sh` §8d,
TECH-198) и пишет в `/var/log/dld-orchestrator/heartbeat-reaper.log`.
**Actual:** В живом crontab нет ни одной строки с reaper. systemd-таймеров нет. Файл лога
`/var/log/dld-orchestrator/heartbeat-reaper.log` **не существует** — значит инструмент не
отработал ни разу.

**Steps to reproduce:**
1. `crontab -l | grep -i reap` → пусто
2. `systemctl list-timers --all | grep -i reap` → пусто
3. `ls /var/log/dld-orchestrator/heartbeat-reaper.log` → No such file or directory
4. `grep -rl heartbeat_reaper scripts/vps/` → только сам модуль, его сиблинги, тесты и
   `setup-vps.sh`; `orchestrator_monitor.py` (единственный, что реально в кроне) его не зовёт

**Evidence:** живой crontab содержит 9 записей (orchestrator_monitor, pop_sync, runner-heal
и т.д.) — reaper среди них отсутствует.
**User impact:** Зависшие claude-runner сессии никто не убивает. Слот занят навсегда,
автопилот встаёт до ручного вмешательства оператора. Ровно тот сценарий, ради которого
TECH-198 и делался. Пересекается с известным паттерном «claude-runner 90min timeout».
**Hint for developers:** либо `setup-vps.sh` §8d никогда не отрабатывал на этой машине,
либо крон-строку затёрли позже. Строка ставится через `crontab -` — её мог снести любой
последующий перезапись-крона.

### F2: Аудит рапортует «чисто» при неверном пути к projects.json

**Severity:** Major
**Reproducibility:** Always
**Expected:** Опечатка в `--projects-json` → ошибка и ненулевой rc (как для `--project` и
`--category`, которые честно дают rc=2).
**Actual:** `WARNING projects.json not found: ...` + `TOTAL: 0` + **rc=0**. Ноль находок и
нулевой код возврата — неотличимо от «дрейфа нет».

**Steps to reproduce:**
```
python3 scripts/vps/lifecycle_audit.py --projects-json /tmp/nope.json --quiet
→ WARNING projects.json not found: /tmp/nope.json
→ TOTAL: 0
→ rc=0
```

**Evidence:** для сравнения, корректные контракты того же CLI:
`--category no_such_cat` → rc=2; `--project zzz_nope` → rc=2; реальный прогон с находками → rc=1.
**User impact:** Мониторинг/крон с опечаткой в пути получает зелёный сигнал и `TOTAL: 0`
навечно. Инструмент, чья единственная задача — ловить дрейф, молча перестаёт его ловить,
рапортуя об идеальном здоровье. Сейчас в проде 2469 находок дрейфа — их бы просто не увидели.
**Hint for developers:** WARNING → fatal с rc=2, как у остальных usage-ошибок.

### F3: `--help` у reaper не показывает справку, а молча запускает боевой прогон

**Severity:** Major
**Reproducibility:** Always
**Expected:** `--help` печатает usage и выходит, ничего не делая.
**Actual:** Ничего не печатает, rc=0, и **выполняет основную логику reaper'а** — то есть
опрашивает pueue и потенциально убивает сессии. argv игнорируется целиком.

**Steps to reproduce:**
```
env -i PATH=/usr/bin:/bin python3 scripts/vps/heartbeat_reaper.py --help
→ 2026-07-28 00:07:58 heartbeat-reaper WARNING pueue status failed: ...
→ rc=0
```
Лог pueue-опроса доказывает, что отработал main(), а не справка. Идентичное поведение
на `--dry-run --nonsense`.

**Evidence:** тот же вывод для `--help` и для мусорных флагов — парсинга аргументов нет.
**User impact:** Оператор, который знакомится с незнакомым инструментом штатным `--help`,
запускает kill-способный инструмент по живым сессиям. Нет ни `--dry-run`, ни способа
посмотреть, что он сделает, не сделав этого.
**Hint for developers:** argparse + `--dry-run`, как у `lifecycle_audit.py` (там всё сделано правильно).

### F4: Reaper неотличим от сломанного — нулевой вывод на успешном прогоне

**Severity:** Minor
**Reproducibility:** Always
**Expected:** Строка вида «проверено N сессий, устаревших 0, убито 0» — свидетельство, что прошёл.
**Actual:** Успешный прогон при двух живых claude-сессиях и свежих heartbeat'ах печатает
**ровно ничего**, rc=0. Ровно то же самое (пустота + rc=0) он печатает, когда бинарь `pueue`
недоступен в PATH и он не проверил ничего.

**Steps to reproduce:**
1. `python3 scripts/vps/heartbeat_reaper.py` → пусто, rc=0 (здоровый прогон)
2. `env -i PATH=/usr/bin:/bin python3 .../heartbeat_reaper.py` → WARNING + rc=0 (не проверил ничего)
   — в обоих случаях rc=0, а в логе крона (`>> ...log 2>&1`) разница видна только внимательному глазу

**Evidence:** heartbeat живой сессии свежий (`updated_at 21:04:32` при `now 21:07:59`) —
то есть входные данные здоровы и тишина означает «нечего убивать», но подтвердить это
из вывода инструмента невозможно.
**User impact:** Усиливает F1 — даже если бы reaper стоял в кроне, пустой лог не отличался бы
от лога никогда не работавшего инструмента. Именно поэтому F1 и не был замечен.
