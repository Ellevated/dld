## Failures

### F1: Marker-aware parser greedily matches example blocks inside spec body
**Severity:** Critical
**Reproducibility:** Always (on TECH-175 itself)
**Expected:** `_parse_allowed_files()` returns the 10 real Allowed Files listed at line 59 of the spec.
**Actual:** Returns 4 placeholder paths (`path/to/file1.py`, `path/to/file2.py`, `path/to/new_file.py`, `tests/path/to/test_file.py`) — these come from the Task 3 *documentation example* (lines ~347–362), wrapped in literal `<!-- DLD-CALLBACK-MARKER-START v1 -->` markers as a code sample.

**Steps to reproduce:**
```bash
python3 -c "
import sys; sys.path.insert(0,'scripts/vps')
import callback; from pathlib import Path
print(callback._parse_allowed_files(Path('ai/features/TECH-175-2026-05-02-spark-spec-template-hardening.md')))
"
# → ['path/to/file1.py', 'path/to/file2.py', 'path/to/new_file.py', 'tests/path/to/test_file.py']
```

**Evidence:** `python3 scripts/vps/spec_verify.py . TECH-175` → "allowed: 4 path(s)" with all 4 MISS, HARD-FAIL. This is exactly what triggered callback's auto-demote to blocked.

**User impact:** Any spec that documents the marker schema (this one, plus future TECH-173 docs) gets its allowlist hijacked by the documentation example. Implementation guard then blocks legitimate work because real commits don't touch placeholder paths. The spec is meta-broken — it cannot describe its own format.

**Hint:** Parser must skip marker blocks inside fenced code (``` ... ```), or require the matching block to also contain a top-level `<!-- callback-allowlist v1 -->` anchor outside fences.
