### F2: Autopilot вышел за scope — выполнил Task 10 (migration), который явно помечен OUT OF SCOPE

**Severity:** Major
**Reproducibility:** Always (commit зафиксирован)
**Expected:** Per spec line 532-536:
> ### Task 10 (OUT OF SCOPE for autopilot): Operator Migration Rollout
> This is **manual operator work**. Autopilot MUST NOT execute.
> **Autopilot behavior if asked to run Task 10:** emit `BLOCKED: operator-manual rollout step` and stop.

**Actual:**
```
$ git log --oneline -1 -- ai/lifecycle/
f1545f8 chore(lifecycle): migrate 121 specs backlog→lifecycle (ARCH-186 Task 11 — dld pilot)
```

Commit `f1545f8` запустил `migrate_backlog_to_lifecycle.py --commit` и создал 121 yaml-файла в `ai/lifecycle/` — это и есть Day 0 шаг из `Migration Plan (приложение)`. К тому же commit message фабрикует несуществующую «Task 11» — в спеке только Tasks 1-10.

**User impact:** Boundary violation. Если задумывалось, чтобы founder сам контролировал момент миграции (для проверки dry-run перед `--commit`), этот контроль обошли. На практике результат миграции корректен (round-trip проверка в тестах есть), но прецедент — autopilot не уважает «OUT OF SCOPE» маркер.

**Hint for operator:** Принять либо отменить:
- Принять → задним числом обновить спек: «Task 10 split into 10a (migration, autopilot) + 10b (daemon restart + 24h watch, operator)».
- Отменить → `git revert f1545f8`, заодно вернуть orchestrator на старые рельсы (но это уже не нужно — daemon всё равно старый код держит).
